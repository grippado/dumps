# Security

dumps is built for a person or a small group publishing their own HTML. This page describes what it defends, what it does not, and what you must do yourself. To report a problem, see [../SECURITY.md](../SECURITY.md).

## Model

- **The public host serves only `dumps/`.** Manifests (`dumps-meta/`), staging, `bin/` and the listing live outside the public docroot. The Caddy example hides dotfiles and redirects `index.html` and `.html` URLs to clean ones. In local mode, `dumpsd --static` applies the same rules: dotfile segments return 404 and only `dumps/` is served.
- **The admin host is behind a login.** The listing page and `/_dumps/api/*` should only be reachable through Cloudflare Access or Tailscale. `dumpsd` also verifies the identity itself (JWT or Tailscale header), the `Origin` and the request shape. See [auth.md](auth.md).
- **`dumpsd serve` listens on loopback only.** It refuses any other `--listen` address. Nothing opens an inbound port on the internet; a tunnel does the exposure.
- **One writer.** Home, listing and manifests are written only by `dumpsd`, under a file lock, using write-then-rename. Publishing uploads to staging and swaps in atomically with rollback.

## Path and id rules

- Ids match `^[a-z0-9][a-z0-9-]{0,62}$`, checked in the CLI, in `dumpsd activate` and `dumpsd apply`, and in the API. This keeps ids from containing `/`, `..` or leading dots.
- The CLI refuses sources in or containing `DUMPS_BLOCKED_PATHS` (exit 2). Use it for directories that must never be published, such as work or client folders.
- For folders, symlinks must resolve inside the folder and not into a blocked path. Content is copied with symlinks resolved, and `.git/` and `.DS_Store` are excluded.
- `listing_dir` in `site.json` cannot be absolute, contain `..`, or point into `dumps/` or `dumps-meta`.
- `DUMPS_ROOT` cannot contain a single quote, and the service arguments are validated against a conservative character set, because they pass through a shell.

## What an attacker can and cannot do

| Attacker | Can | Cannot |
|----------|-----|--------|
| Anyone on the internet | Read published dumps and the home. Guess ids (random 10-character ids are not guessable in practice, but a link is not a secret once shared) | Read manifests, staging or the listing, call the admin API, write files |
| A page visited by an admin (CSRF) | Send a cross-site request to the admin host | Pass the `Origin` check or carry a valid Access token |
| Someone who reaches the admin API without a login | Nothing: `403` | Archive, rename or delete |
| A logged-in user who is allowed by your policy | Archive, unarchive, rename, delete any dump | Publish or change content (that needs ssh to the server), run commands |
| An ssh user with your key | Everything | |

Archived dumps are hidden from the home but still public to anyone with the link. Use it for tidiness, not for privacy. Do not publish anything you would not want read.

## Third-party HTML shares your origin

Every dump is served from the same origin, for example `https://dumps.example.com`. Scripts in one dump can read the cookies and `localStorage` of every other dump on that host, and can fetch their files. The injected bar also sets a small `dumps_tip` cookie there.

Publish only HTML you wrote or trust. For content you do not trust (generated by others, from an unknown source), use a separate domain, and a separate `dumps` instance with its own root.

In local mode the admin API shares the origin of the dumps (`--auth none` accepts any loopback request with a matching `Origin`). A local dump with JavaScript could call `/_dumps/api/*` and archive or delete other dumps. Treat local mode as single-user and trusted-content only.

`tagline_html`, `host_card_html` and `footer_html` in `site.json` are inserted into the home as raw HTML. Only the server owner writes them.

## Secrets and files that must never be committed

- Tunnel credentials (`~/.cloudflared/<TUNNEL-UUID>.json`) and the `cert.pem` from `cloudflared tunnel login`.
- ssh private keys.
- Your real CLI config (`~/.config/dumps/config`) and any `site.json` with private text. The Access AUD tag is not a secret, but it identifies your setup, so keep the config private too.

Commit `examples/` only, with `example.com` hostnames.

## Privacy notes

- With `DUMPS_GA_ID` set, every dump and the home load `googletagmanager.com` and report page views and the `share` and `dumps_clean_mode` events. Leave it empty to disable it.
- Open Graph tags include the dump URL and, when present, the author names.
- The share buttons open WhatsApp and Telegram share links on click. Nothing is sent before that.
