Verdict

Cloudflare takes the admin seat, Tailscale takes the shortcut

Five ways to put a dumps server on the internet were weighed. Only two give the browser admin a login that dumpsd can actually verify.

The recommendation

Already have a domain on Cloudflare? Use Cloudflare Tunnel and Access. Otherwise, use Tailscale Funnel and serve for the lowest effort.

The reason that decided it: native auth for the admin. dumpsd has a mode for Cloudflare Access (access) and a mode for Tailscale (tailscale). ngrok, frp and Caddy on a VPS have none, so with those you expose only the public listener and manage dumps from the CLI.

dumps asks very little of the layer that faces the internet. The public host has to reach Caddy on 127.0.0.1:8081. If you want a browser admin, the admin host has to reach Caddy on 127.0.0.1:8080 behind a login that dumpsd can verify. Everything else is taste.

Cloudflare does it with no open inbound port: a tunnel carries two hostnames to two loopback listeners, and Access guards the admin one. Tailscale does it with less work: Funnel publishes the public listener on your ts.net name, and tailscale serve keeps the admin inside your tailnet, adding the header dumpsd trusts.

ngrok and frp will happily publish the public listener, but dumpsd cannot read their logins. Caddy on a VPS gives you any domain and automatic HTTPS with no third party in the traffic path, at the price of the most work.

For a public site with no admin UI, the docs are blunt: any option works.

Classifieds

One notice per option

Cloudflare Tunnel and Access

No open inbound port. Two hostnames, two listeners.

Best for
Anyone whose domain already lives on Cloudflare and who wants the browser admin.
Watch out for
Create the Access application for the admin hostname before its DNS record exists. Treat the tunnel credentials file as a secret. Do not put an Access app on the public hostname.
Cost
A domain on Cloudflare; check current plan limits.

Tailscale Funnel and serve

Funnel the public port, serve the admin port.

Best for
The lowest setup effort that still gives the admin a native login.
Watch out for
You get the ts.net name, not your own domain. dumpsd trusts the header from any loopback connection, so only tailscale serve may reach the admin listener. DUMPS_ADMIN_ORIGIN must include the port. Use DUMPS_TAILSCALE_ALLOW if the tailnet has other people.
Cost
Check current plan limits.

ngrok

A public URL for 8081, fast.

Best for
A quick public listener when admin work happens over ssh.
Watch out for
Its login features are not something dumpsd can verify. Custom domains depend on your plan.
Cost
Check current plan limits.

frp on a VPS

frps on the VPS, frpc at home.

Best for
A custom domain through a VPS with a public IP you already run.
Watch out for
No native admin auth. Expose only the public listener unless you add your own authenticated layer.
Cost
A VPS.

Caddy on a VPS

Reached home through WireGuard or an ssh reverse tunnel.

Best for
The most control: any domain, automatic HTTPS, no third party in the traffic path.
Watch out for
The most work: VPS, tunnel and keep-alive. Keep the admin listener off the VPS.
Cost
A VPS.

Editorial: what would change the decision

Opinion

Drop the browser admin and the race opens up. dumps archive, unarchive, edit and rm run on the server over ssh, so anyone who already has ssh needs no login layer, and for a public site with no admin UI any option works.

Then pick on the other rows: ngrok for low effort, frp if you already rent a VPS, Caddy on a VPS if you want any domain with no third party in the traffic path and do not mind the most work. If your own domain is a hard requirement, Tailscale drops out, because Funnel serves your ts.net name. Keep the browser admin and want your own domain, and Cloudflare is the pick. Commands and plan limits of these tools change, so check their current docs before you commit.

Do not use DUMPS_AUTH=none to skip the login. The CLI refuses it for a service.
