# Recipe: doc (think like a technical writer)

Use for reference material, a how-to, a runbook, a spec or meeting notes worth keeping.

1. **Title and purpose.** What this doc is for and who should read it, in two lines.
2. **Table of contents.** Sticky on wide screens, at the top on phones, generated from the
   `h2` and `h3` headings, with anchors.
3. **Tasks as numbered steps.** One command per code block, each block with a copy button.
   Say what success looks like after the step.
4. **Reference as tables.** Options, flags or fields in a table: name, default, meaning.
5. **Callouts.** Note, warning and danger boxes, used sparingly.
6. **Last updated** date at the top.
